> 본 문서는 모델 학습 초보자가 AI(Devin 등)에게 작업을 위임할 때 참고할 수 있도록

## 0. 사전 지식: 이 프로젝트가 하는 일

- **입력**: 물류 센터 물품 이미지 + 상품의 물리적 가로/세로 크기(width, height)
- **출력**: KAN_code 앞 4자리 기준 107개 클래스 중 하나
- **방법**: SK-Res2Net-101 백본 + Dynamic MLP (메타데이터로 feature를 동적 변조)
- **흐름**:
  1. 이미지 → 백본(CNN) → 2048차원 feature
  2. 가로/세로 → sin/cos 인코딩 → 4차원 → FCNet → 256차원 메타 임베딩
  3. 이미지 feature + 메타 임베딩 → Dynamic MLP Fusion → 최종 분류

### 1.3 PyTorch 설치 (GPU 지원)

PyTorch는 GPU 모델에 따라 설치 명령이 다릅니다. **반드시 GPU에 맞는 CUDA 버전을 설치해야 합니다.**

#### RTX 50xx 시리즈 (Blackwell, sm_120) — CUDA 12.8 이상 필수

RTX 5060/5070/5080/5090 등 Blackwell 아키텍처는 CUDA 12.8 이상의 PyTorch만 호환됩니다.
구버전(CUDA 12.1 등)을 설치하면 `no kernel image is available for execution on the device` 오류가 발생합니다.

```bash
# Windows / Linux 공통 (CUDA 12.8)
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
```

#### RTX 30xx / 40xx 시리즈 (Ampere/Ada) — CUDA 12.1 이상

```bash
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
```

#### CPU 전용 (GPU가 없거나 디버깅용)

```bash
pip install torch torchvision
```

> **주의**: `pip install torch`만 실행하면 CPU 전용 버전이 설치될 수 있습니다.
> GPU를 사용하려면 반드시 `--index-url`로 CUDA 버전을 지정하세요.

## 2. 데이터 준비

### 2.1 데이터 구조 이해

**원본 데이터 구조** (samples/ 또는 서버의 전체 데이터):

```
samples/
  01.원천데이터/                    ← 이미지
    01_입고물품/                    ← 입고물품 (이 모델의 학습 대상)
      01_가공식품/01_조미료/01010110_8809251219122/
        01010110_8809251219122_1_1.jpg
        ...
    02_출고물품/                    ← 출고물품 (별도 모델의 학습 대상)
      01_가공식품/01_조미료/01010102_8809162740524/
        ...
  02.라벨링데이터/                  ← 어노테이션 (동일 폴더 계층)
    01_입고물품/01_가공식품/01_조미료/01010110_8809251219122/
      01010110_8809251219122_1_1.json
      ...
    02_출고물품/...
```

- **입고물품(`01_입고물품`)과 출고물품(`02_출고물품`)은 서로 다른 모델의 학습 대상**
  → `prepare_data.py --category` 파라미터로 선택
- leaf 폴더명 = `{KAN_code}_{product_id}` (예: `01010110_8809251219122`)
- 파일명 = `{KAN_code}_{product_id}_{shot_id}_{cam_id}.jpg`

**학습용 구조** (datasets/ — `dataset.py`가 기대하는 형태):

```
datasets/
  train/          ← 학습 이미지 (평면 구조, 파일명만)
  train_ann/      ← 학습 어노테이션 (평면 구조)
  tta/            ← 검증 이미지  ※ val/이 아니라 tta/ 임
  tta_ann/        ← 검증 어노테이션
```

> **주의**: 입고/출고 모델은 동일한 `datasets/` 경로를 공유하므로,
> 카테고리를 바꿀 때는 반드시 `--clean` 옵션을 사용해 기존 데이터를 지우고
> 새로 생성해야 합니다. 또는 `--dst`로 별도 경로를 지정할 수도 있습니다.

### 2.2 데이터 재분포 실행

```bash
# 입고물품 (기본값): samples/ → datasets/, 8:2 분할
python prepare_data.py --clean

# 출고물품: 별도 모델 학습용
python prepare_data.py --category outbound --clean

# 소스 경로를 세미콜론(;)으로 여러 개 지정 (데이터가 여러 디렉토리에 분산된 경우)
python prepare_data.py --src "samples;D:/more_samples;E:/extra" --clean
python prepare_data.py --src "samples;D:/more_samples" --category outbound --clean

# 분할 결과만 확인 (복사 없음)
python prepare_data.py --dry_run
python prepare_data.py --category outbound --dry_run

# 분할 비율 변경
python prepare_data.py --val_ratio 0.15 --seed 42

# 입고/출고를 별도 디렉토리로 분리 (동시 유지하고 싶을 때)
python prepare_data.py --category inbound  --dst datasets_inbound  --clean
python prepare_data.py --category outbound --dst datasets_outbound --clean
```

**`--src` 다중 소스 지정**:
- 세미콜론(`;`)으로 구분된 여러 경로를 순차적으로 스캔하여 상품 목록을 병합.
- 동일 상품 폴더명이 여러 소스에 중복될 경우 `(src, folder)` 키로 중복 제거.
- 데이터가 여러 디스크/디렉토리에 분산되어 있을 때 유용.

**`--category` 파라미터**:
| 값 | 의미 | 대상 폴더 |
|---|---|---|
| `inbound` (기본) | 입고물품 | `01_입고물품` |
| `outbound` | 출고물품 | `02_출고물품` |

**분할 기준**:
- 상품 단위(leaf 폴더)로 분할 → 동일 상품의 이미지가 train/val에 섞이지 않음
- KAN_code(앞 4자리) 기준 stratified → 각 클래스가 train/val에 고르게 분포
- 상품 폴더가 1개뿐인 KAN_code는 train에만 배치 (val에 해당 클래스 없음)

> **AI 위임 시**: "prepare_data.py를 실행해서 samples 데이터를 datasets로
> 재분포해줘. --clean 옵션으로 기존 데이터 지우고 새로 만들어줘."

## 3. 학습 실행

### 3.1 Windows 로컬 디버깅 (소량 데이터)

```bash
python train.py ^
  --name sk2_dynamic_mlp ^
  --data NIA29_input ^
  --data_dir datasets ^
  --model_file sk2res2net_dynamic_mlp ^
  --model_name sk2res2net101 ^
  --batch_size 8 ^
  --num_workers 0 ^
  --start_lr 0.01 ^
  --stop_epoch 3 ^
  --warmup 1
```

> **PowerShell 주의**: PowerShell에서 `^` 줄연결자가 동작하지 않습니다.
> CMD(`cmd.exe`)에서 실행하거나, PowerShell에서는 한 줄로 작성하세요:
> ```powershell
> python train.py --name sk2_dynamic_mlp --data NIA29_input --data_dir datasets --model_file sk2res2net_dynamic_mlp --model_name sk2res2net101 --batch_size 8 --num_workers 0 --start_lr 0.01 --stop_epoch 3 --warmup 1
> ```

**Windows 주의사항**:
- `--num_workers 0`: Windows에서 다중 워커 시 pickle 오류 발생 가능
- `--batch_size 8`: GPU 메모리에 따라 조절 (RTX 5060 8GB 기준 8~16)
- `--stop_epoch 3`: 디버깅이므로 3 epoch만 실행
- `--start_lr 0.01`: 소량 데이터이므로 lr 낮춤
- 첫 배치는 CUDA 커널 JIT 컴파일로 인해 30초 정도 소요될 수 있음 (이후 정상 속도)
- GPU가 없어도 자동으로 CPU로 동작 (로그에 "CUDA not available - using CPU" 표시)

### 3.2 Linux 서버 본 학습 (전체 데이터)

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3 python3 train.py \
  --name sk2_dynamic_mlp \
  --data NIA29_input \
  --data_dir /path/to/datasets \
  --model_file sk2res2net_dynamic_mlp \
  --model_name sk2res2net101 \
  --pretrained \
  --batch_size 512 \
  --num_workers 32 \
  --start_lr 0.04 \
  --stop_epoch 100 \
  --warmup 2
```

**서버 설정 시 확인사항**:
1. `models/sk2res2net_dynamic_mlp.py` 1070줄의 사전학습 경로 수정
2. `--data_dir`을 서버의 실제 데이터 경로로 지정
3. GPU 수에 따라 `--batch_size` 조정 (GPU당 약 64~128)
4. `--num_workers`는 CPU 코어 수에 따라 조정 (보통 코어 수의 절반)

### 3.3 학습 중 확인

**로그 위치**: `logs/{data}/{name}/` 아래의 `{timestamp}_train.log`

```bash

  --name sk2_dynamic_mlp \

  --data_dir datasets \
```

## 6. 문제 해결 가이드

### 6.1 일반적 오류

| 오류 | 원인 | 해결 |
|------|------|------|
| `AssertionError: Torch not compiled with CUDA enabled` | CPU 전용 PyTorch 설치됨 | 1.2절에 따라 CUDA 지원 PyTorch 재설치 |
| `RuntimeError: no kernel image is available for execution on the device` | RTX 50xx(Blackwell)에 구버전 CUDA PyTorch 설치 | CUDA 12.8 이상 PyTorch 설치 (`--index-url https://download.pytorch.org/whl/cu128`) |
| `UnicodeDecodeError: 'cp949' codec` | Windows에서 JSON 파일을 UTF-8 없이 읽음 | `dataset.py`는 수정 완료. 다른 스크립트에서도 `open(f, encoding='utf-8')` 사용 |
| `UnicodeEncodeError: 'cp949' codec` | Windows 콘솔 로그에 특수문자(em-dash 등) | `prepare_data.py`는 수정 완료. 로그 메시지에 ASCII 문자 사용 |
| `FileNotFoundError: Annotation file not found` | 이미지에 대응하는 JSON이 없음 | `prepare_data.py --clean` 재실행 |
| `KeyError: KAN_code not found` | JSON의 attributes에 KAN_code 없음 | 해당 JSON 파일 확인, `prepare_data.py`가 검증 후 스킵함 |
| `ValueError: KAN_code XXXX not found in predefined list` | KAN_code가 107개 리스트에 없음 | 2026-09부터 `dataset.py`/`prepare_data.py`가 리스트 외 코드를 자동 제외. 그래도 발생하면 어노테이션의 KAN_code가 파일명과 다른 것이므로 해당 JSON 확인. 새 클래스를 추가하려면 `kan_code_list`에 코드 추가 + `num_classes` 수정 + `eval.py`의 `number_labels` 동기화 필요 |
| `CUDA out of memory` | batch_size 너무 큼 | `--batch_size` 감소 (RTX 5060 8GB 기준 8~16) |
| `RuntimeError: DataLoader worker` (Windows) | 다중 워커 문제 | `--num_workers 0` |
| `FutureWarning: torch.cuda.amp` | PyTorch 2.x API 변경 | 무시해도 동작에는 문제없음 |

### 6.2 학습이 안 될 때 점검 순서

1. **데이터 확인**: `python prepare_data.py --dry_run`으로 분할 결과 확인
2. **1 epoch만 실행**: `--stop_epoch 1`로 빠르게 오류 확인
3. **로그 확인**: `logs/NIA29_input/{name}/`의 `.log` 파일
4. **GPU 확인**: `nvidia-smi` (Linux) 또는 작업 관리자 (Windows)
5. **메모리 확인**: batch_size를 1로 줄여서 테스트

### 6.3 정확도가 오르지 않을 때

- **데이터 부족**: 클래스당 이미지 수 확인 (일부 클래스는 1~6장뿐)
- **학습률**: `--start_lr` 조정 (0.01 ~ 0.1 범위에서 실험)
- **epoch 수**: `--stop_epoch` 증가 (100 → 200)
- **mixup**: 너무 적은 데이터에서는 mixup이 방해가 될 수 있음
- **데이터 증강**: `dataset.py`의 transform에 RandomResizedCrop 등 추가 고려

## 8. 전체 워크플로우 요약

```
[Windows 로컬 — 디버깅]
  1. 가상환경: python -m venv .venv → 활성화
  2. 환경 설정: PyTorch CUDA 12.8 설치 (RTX 50xx) 또는 CPU 버전
     pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
     pip install numpy pillow tqdm scikit-learn matplotlib thop
  3. 사전학습 가중치: checkpoints/ 에 배치
  4. 데이터 준비: python prepare_data.py --clean
     (데이터가 여러 경로에 분산 시: --src "samples;D:/more_samples")
  5. 디버그 학습: python train.py (batch_size=8, stop_epoch=3)
     → GPU 자동 감지 (CUDA 있으면 GPU, 없으면 CPU)
  6. 오류 수정 및 검증

[Linux 서버 — 본 학습]
  1. 코드 전송 (소스만, .venv/·datasets/·*.pth 제외 — .gitignore 참조)
  2. 패키지 설치: pip install -r requirements.txt --index-url <CUDA URL>
  3. 사전학습 경로 수정: models/sk2res2net_dynamic_mlp.py
  4. 전체 데이터로 prepare_data.py 실행
     (여러 소스 시: --src "path1;path2;path3")
  5. 본 학습: python train.py (batch_size=512, stop_epoch=100)
  6. 평가: python eval.py --resume ... --evaluate
  7. 결과 분석 및 하이퍼파라미터 튜닝
```
